### Dependency contracts checked

Locked versions are `coreaudio-rs 0.13.0`, `rtrb 0.3.4`, and Symphonia `0.5.5`; their installed sources, not remembered historical line numbers, were inspected.

- Symphonia FLAC `src/decoder.rs:171` and ALAC `src/lib.rs:571` promote sub-32-bit samples into high bits of s32. `symphonia-core/src/audio.rs:949` represents raw i24 as `[u8; 3]`. This matches Pulse's shifts and byte widths.
- rtrb `src/chunks.rs:281` and `:408` implement bounded partial slice copies, with chunk commits publishing progress. Pulse uses one producer and one consumer; the only off-callback consumer access is the raw sink's post-stop drain. Dropping one ring endpoint does not invalidate the other endpoint's storage.
- `coreaudio-rs/src/audio_unit/render_callback.rs:270` converts the first interleaved AudioBuffer to bytes without a per-callback allocation, but asserts that the driver's byte count equals frames × channels × sample size before Pulse's closure runs. A malformed callback can therefore panic outside the worker catch. `:475` allocates the callback once during registration; a registration property-write error leaves that raw boxed callback unowned, a dependency leak on that failure path. `src/audio_unit/mod.rs:341` stops, uninitializes, frees callbacks, then disposes, ignoring destructor errors. Treat successful quiescence as a dependency/OS contract, not a Rust mutex guarantee.
- The installed Xcode `AudioHardware.h` describes disabled IOProc streams as null data with a nonzero byte size. Its `AudioDeviceStop` declaration at line 1473 and Apple's [AudioDeviceStop documentation](https://developer.apple.com/documentation/coreaudio/audiodevicestop(_:_:)) do not explicitly state that all in-flight callback invocations have returned. This is an unresolved assumption already noted in review 78, not a newly proven race.
- A suspected ranged-rate mismatch was dismissed: Apple's [AudioStreamRangedDescription contract](https://developer.apple.com/documentation/coreaudio/audiostreamrangeddescription) specifies a wildcard `mSampleRate` for multi-rate ranges and equal fixed/min/max rates otherwise. Pulse's universal candidate code resolves the wildcard correctly; inconsistent fabricated ranges are not evidence of a driver-valid regression.

## Confirmed pre-existing findings

### F1 · P1 — DoP safety is not enforced at the engine boundary

**Pointers:** `controller/mod.rs:71` chooses the DSD decoder by extension; `controller/decoder.rs:10` exposes only `PcmFormat`; `controller/worker.rs:496`, `:743`, `:619` restart that decoder on the requested backend without retaining a DoP requirement. The float conversion and fade are at `auhal_engine.rs:264` and `auhal.rs:89`.

**Trigger/consequence:** send `PlayFile` for a DFF/DSF to a universal controller, or switch an active DSD track from Integer to Universal with `SetOutputDevice`. The engine accepts it and feeds DoP bytes into float conversion/gain/resampling, violating feature 71's safety rule. These bytes can be heard as PCM noise on an output that does not recognize/preserve DoP.

**Current app mitigation and residual race:** normal app play/resume/lookahead/restore checks refuse unsafe DSD, and `crates/pulse-app/src/backend/playback/devices.rs:275` / `:480` call `stop_before_unsafe_dsd_output_change`. However, that helper (`crates/pulse-app/src/backend/playback/controller.rs:852`, especially `:863`) checks the displayed `source_path`, not a pending play target or the worker's current decoder. An output change before the DSD `NowPlaying` event is drained can inspect the preceding PCM path/None, omit Stop, and enqueue the unsafe switch after DSD play. The headless engine bypass is reproduced; this UI timing window is a caller trace, not a live-app reproduction.

**Coverage/reproduction:** existing app tests cover known/current DSD refusal and normal mode changes. A temporary worker test used the real `dsd-interleave.dff` decoder and `FakeBackend`: Integer play → `set_output_device(8, Universal { exclusive_mode: false })` → `pump`; the universal fake accepted all 200 DoP frames at 176400 Hz and state remained Playing. No physical backend was instantiated.

**Next step:** enforce the decoded source's DoP requirement in the engine before backend start, lookahead splice/rebuild, and mode/device restarts; retain app checks for helpful UX. Add regressions for direct commands and the pending-play output-switch race. Do not solve this with a filename-only UI check. No fix is included here. Audible severity and device behavior remain hardware-only.

### F2 · P2 — A sink that never advances stays Playing indefinitely

**Pointers:** `controller/worker.rs:882`, especially `:891`; initial `backend_has_progressed: false` at `:800` and `:1043`.

**Trigger/consequence:** backend start succeeds, frames are fed, but the callback consumes zero frames forever. The guard clears `stalled_since` whenever `backend_has_progressed` is false, so the two-second timeout never starts. Playback stays at zero with no error; the integer lease can remain held until Stop/quit. This also affects restarts and format-changing boundaries.

**Coverage/reproduction:** existing stall tests first establish progress and then freeze it. A temporary direct Worker probe used `position_limit = 0`, fed 2000 frames, advanced its injected clock by ten seconds three times, and pumped after each advance. It remained Playing with `stalled_since == None`. No sleeps or hardware were needed for this probe.

**Next step:** distinguish startup grace from post-progress stall, arm a bounded watchdog once source data is owed, and retain the current no-data/paused exemptions. Pin zero-progress start and restart cases with the injected clock. The exact driver failure that would trigger this still needs hardware/fault-injection evidence.

### F3 · P2 — An odd-length seamless DoP boundary repeats its marker

**Pointers:** `decode_dsd/mod.rs:69`, `:204`; `decode_dsd/dsf.rs:96`, `decode_dsd/dff.rs:73`; `controller/worker.rs:923`, `:954`.

**Trigger/consequence:** an outgoing DSD track contributes an odd number of DoP frames, and the next DSD decoder is spliced into the same-format ring. Every decoder starts with marker `0x05`, so the outgoing last frame and incoming first frame both carry `0x05`. The uninterrupted stream violates the alternating marker sequence. The DAC may mute, relock, or lose DoP recognition; the precise reaction to one duplicate marker was not tested.

**Coverage/reproduction:** the committed DSF expectation contains two frames and DFF expectation 200; those even-length fixtures do not expose the join. The temporary probe copied the DSF fixture, changed its little-endian sample-count field at byte offsets 64–71 to 16 (retaining valid padded channel blocks), opened two decoders, and decoded one frame from each. Their consecutive left-channel marker bytes were `[0x05, 0x05]`. The worker's unchanged splice performs no marker reconciliation.

**Next step:** decide how uninterrupted DoP output carries marker phase between decoders, then test odd/even boundaries, seeked outgoing tracks, both containers, and PCM↔DoP transitions. This is separate from the already accepted zero-fill/stop relock behavior, and no seamless-transport feature work is folded into this refactor.

### F4 · P2 — Universal Exclusive does not restore device formats

**Pointers:** `auhal_engine.rs:45`, `:89`, `:246`, `:259`; contrast `integer_engine/release.rs:78` and `hal/ownership.rs:217`.

**Trigger/consequence:** Universal Exclusive changes nominal rate and attempts a physical-format change, then pauses/releases or fails later during setup. It owns a hog guard but no capture/restore guard, so releasing the hog leaves the changed device state. Physical-format selection errors are deliberately ignored, including a timeout after a possibly effective write.

**Status/evidence:** this is review 78 §4.5's existing observation, reverified in current code, not a new discovery. Tests verify Shared performs no reconfiguration and Exclusive requests rate before format; none verify universal restoration. The absence of restoration is source-confirmed; actual before/after driver state was not inspected.

**Next step:** triage whether Universal Exclusive should restore nominal and physical state on normal and partial-failure release. If adopted, add failure-order tests and a device check. Keep it separate from the mechanical split and from feature 77's manual unlock UX.

### F5 · P3 — A subscription created after worker exit never disconnects

**Pointers:** `controller/mod.rs:89`, `:138`, `:162`.

**Trigger/consequence:** call `shutdown()` while retaining the public controller, then `subscribe()`. Worker exit already cleared the subscriber list; `subscribe` adds a fresh sender to that list without checking exit state. Its receiver stays connected and empty until the controller/list is dropped. The same window exists after a caught worker panic.

**Coverage/reproduction:** the existing panic test subscribes before the panic and correctly sees Disconnected. The temporary probe called shutdown, subscribed, then asserted `try_recv() == Err(Empty)` instead of Disconnected. The current app subscribes during installation (`crates/pulse-app/src/backend/playback/controller.rs:12`), so no current app symptom is claimed.

**Next step:** make closed subscriber state explicit, atomically with subscription registration, and return an already-disconnected receiver after exit. Add after-shutdown and concurrent-exit subscription tests when triaged.
